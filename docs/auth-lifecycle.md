# 로그인 및 재접속

기존 시작 흐름은 세션 복원 뒤 프로필과 여러 데이터 조회를 모두 기다렸고,
인증 이벤트에서도 같은 조회를 반복했다. 응답이 끝나지 않으면 로딩을 해제할
경로가 없었다. 프로필 조회 실패와 실제 미가입 상태도 모두 `null`로 처리했다.
실제 기기의 특정 장애 원인은 기기 로그 없이 단정하지 않는다.

## 현재 흐름

- `useAuthSession`과 `sessionLifecycle`이 세션 복원, 프로필 확인, 준비 완료,
  로그아웃, 오류 상태를 관리한다. 인증 이벤트 안에서는 서버 조회를 실행하지 않는다.
- 세션 복원과 프로필 확인은 각각 15초, 네트워크 요청은 12초, 저장소 접근은
  5초 제한을 둔다. 시간 초과 시 재시도와 로그인 화면 복귀를 제공한다.
- 같은 사용자의 토큰 갱신은 세션만 교체한다. 이전 계정의 지연된 응답은 폐기한다.
- Native 앱의 활성/비활성 상태에 맞춰 토큰 자동 갱신을 시작/중단한다.
  웹의 탭 가시성 처리는 SDK에 맡긴다.
- 카카오 콜백은 동일 요청을 한 번만 처리한다. 저장된 세션을 복원한 경우
  오래된 초기 실행 URL을 다시 적용하지 않는다. Native 로그인 대기는 최대 2분이다.
- 명시적 로그아웃/복구는 해당 Supabase 인증 키만 지운다. 이전 클라이언트의
  늦은 토큰 저장을 차단하고 클라이언트를 새로 만든다. `storage.clear()`는 사용하지 않는다.
- 일지·지출·굿즈 등은 로그인 완료 후 별도로 불러온다. 캐시는 계정별 키를 사용한다.
  기존 공용 캐시는 삭제하지 않지만 소유자를 확인할 수 없어 다른 계정에 자동 배정하지 않는다.
  서버 데이터가 새 캐시를 채운다.

## 검증

`npm test`는 Node.js 테스트 러너를 사용한다. 세션 복원 지연/재시도, 프로필 오류,
로그아웃/계정 전환 경쟁, 중복 콜백, Native 브라우저 복귀, 활성 상태 갱신,
인증 키만 초기화하는 동작을 검증한다. 실제 Supabase SDK에는 테스트 저장소와
가짜 HTTP 응답을 주입해 반복 실행, 만료 토큰 갱신, 무효 토큰 처리를 확인한다.
테스트에서 실제 카카오 계정이나 운영 데이터는 사용하지 않는다.

웹/Native JS 번들 확인:

```sh
npx expo export --platform all --output-dir .expo/auth-build
```

실제 기기에서는 새 앱 빌드를 설치하되 데이터를 지우지 않고 다음을 확인한다.

1. 기존 로그인 상태에서 앱 강제 종료 후 재실행.
2. 토큰 만료 이후 재실행, 백그라운드 전환 후 복귀.
3. 네트워크 차단 후 시작 → 오류 안내 → 연결 복구 → 다시 시도.
4. 로그인 화면 복귀 후 카카오 재로그인, 사용자 취소, 카카오톡 경유 복귀.
5. 로그인 브라우저가 열린 동안 앱 종료 후 콜백으로 재실행.

참고: [Supabase React Native 안내](https://supabase.com/docs/guides/auth/quickstarts/react-native),
[인증 이벤트](https://supabase.com/docs/reference/javascript/auth-onauthstatechange).
